### R4-F1 (storage-boundary test is blind) - high

> **Durable-storage sentinel cannot exercise storage-only minimization**
> (`skills/measure-instrumentation-spec/references/TEMPLATE.md:159-161`)
> The sentinel is selected from a data class forbidden to cross egress. A working egress filter
> therefore removes it before storage, so its absence from durable storage proves nothing about
> storage minimization. Conversely, selecting a storage-only forbidden class would make the required
> collector-absence assertion invalid. Ineffective storage filtering can still persist raw tenant
> data while every listed test passes.
> Recommendation: Use separate boundary-specific sentinels. Assert an egress-forbidden sentinel is
> absent at the collector, and assert a storage-forbidden but egress-allowed sentinel is present at
> the collector and absent from durable storage. Repeat persistence assertions during forced failure
> paths.

**Verification: CONFIRMED. The sharpest finding of the cycle, and a logic error rather than a fact
error.** One sentinel cannot test two boundaries: if egress filtering works, an egress-forbidden
sentinel never reaches storage, so its absence there is guaranteed by the egress filter and a
completely broken storage filter passes. The round-3 fix made the test look stronger while testing
less. **Fixed with two sentinels**: A (egress-forbidden, absent at collector) and B (egress-allowed
but storage-forbidden, **present at collector** and absent from storage), with the present-at-collector
assertion being what isolates the storage boundary. A spec allowing no such class must now record
that the storage boundary is untested by construction rather than carry a test that cannot fail.
